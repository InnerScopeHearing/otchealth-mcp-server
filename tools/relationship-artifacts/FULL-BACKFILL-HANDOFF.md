# Full backfill executable and authorization

This combined draft follows PR328 548705cff758d0badfba5387ee7b2dd709c4ba02 and targets main so the full hosted CI workflow is eligible. PR316 dependency and CTO PR190 release holds remain unchanged. Local test results are not a hosted gate or production proof.

The ordinary command is node tools/relationship-artifacts/full-backfill-cli.mjs --config <absolute runtime.json> --once. It defaults to full relationship processing, fixed-imports actual CTO modules, builds the prepared-source adapter, broker operation store, history authority, durable outbox and publisher, and invokes the actual catalog host. No caller-injected relationshipPipelineFactory is required. The older CTO controller-cli remains extraction-only and is not the full-backfill command.

Runtime JSON schema relationship-backfill-runtime-v1 contains absolute cto_root, host_config and outbox_directory, producer, explicit review_mode and registry. review_mode is signed-review or candidate-only. Signed mode requires registry {id,version,public_key_file,authority}, using the actual authenticated registry client and pinned Ed25519 verifier before extraction. Candidate mode requires registry:null and imports createCandidateOnlyReview; it preserves source-cited unverified candidates and does not request identity-registry access. Both modes retain extraction, current source authorization, active-run and artifact policy enforcement. A candidate-only record is never a verified identity or semantic conclusion.

--check loads local dependencies and reports configured with live_verified:false. Missing components produce not-ready and nonzero exit. Running modes consult the required remote authority; disabled or held states do not become successful full processing. No live source or credential values are printed. The existing CFO token is read through a callback at runtime and the existing worker filters its child environment.

POST /relationship-artifacts/v1/:runId/:producerId/authorize issues request-bound provenance for the actual durable resolver and artifact store. It reuses current policy, authenticated caller, cohort admission and active-run checks. History write is available before the first artifact; reads additionally verify exact stored versions, content hashes, producer/run metadata and encryption. Artifact preflights bind their own put/get action and digest/version. The fixed store id is relationship-gateway-v1. This adds no policy authorization on its own; absent policies deny.

Prepare-RelationshipBackfill.ps1 writes runtime/host/install configuration and copies Start-RelationshipBackfill.ps1, then executes only --check. It neither registers nor starts a scheduled task. Start defaults to Check and accepts Once, Watch or Recover only when invoked. Configuration, executable and module paths are trusted operator-controlled code inputs; install them in a directory restricted to the designated CFO host operator. No secrets are written. Persistent outbox storage must survive process restarts. This is CFO-only; company CLO needs its separately authorized lane and personal CLO stays outside this runtime.

Additional authority tests use the actual durable adapter and new client/server rather than fabricated allow callbacks. Ordinary subprocess regression loads the actual factories without caller injection and emits relationship recovery before a disabled cohort stops work. This uses synthetic transport and a never-executed synthetic Codex file. Candidate-only ordinary executable validation passed with registry:null and no registry request. Production still requires release-owner merge/CI approval, gateway deployment, correct live artifact/cohort/publication policy, a configured CFO host, and an observed source-to-cited-relationship-to-fresh-query run. This draft does not activate or claim that run.
